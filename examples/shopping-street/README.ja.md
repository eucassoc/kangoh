# 例：商店街の共通ポイント

公開済みの kangoh パッケージで作った、架空の商店街（3店）のデモです（画面は日本語）。
誰も会員登録せず、誰も顧客データベースを持ちません。

流れは [demo.mp4](demo.mp4)（約2分）で見られます。

## 動かし方

Node 20 以上が必要です。

```sh
cd examples/shopping-street
npm install
npm start          # http://127.0.0.1:8900/
```

運営のサービス（レシート窓口と照合サービス）は 8901 番のポートで動きます。
起動するたびに、また「最初から」を押すと、空の状態から始まります。

## 見られること

画面下のバーでページを切り替えます。

1. **お客さまの手元**：パン工房こむぎの昨日のレシートと、お客さまのアプリです。
   アプリは申請ごとに新しい鍵を作り、レシートの内容とその鍵だけを送ります。
2. **こむぎの端末**：1日1回の確認です。「別の人が同じレシートで申請する」を押すと、
   レシートを撮影した人を想定して、同じ番号を別の金額で申請します。先着の申請が
   優先され、後からの申請は重複として先頭に出ます。承認するとお店の鍵でポイントが
   発行され、重複の申請は却下されます。
3. **喫茶ひだまり**：レジのお客さま向け画面に、お店の鍵で署名したQRを出します。
   QRからの申請は確認なしで、お店の次の同期で発行されます。
4. **雑貨つむぎ**：20ポイントで支払います。こむぎの18ポイントを丸ごと、
   ひだまりの6ポイントのうち2ポイントを使い、残りの4ポイントは運営の照合サービスが
   お釣りとして発行します。
5. **コピーしたアプリ**：アプリのコピーが、使い終わった18ポイントを喫茶ひだまりで
   もう一度提示します。照合サービスがその場で断ります。
6. **運営の精算**：各店の記録から精算します。こむぎが18、ひだまりが2を支払い、
   つむぎが20を受け取ります。記録にあるのはダイジェストだけです。

デモを一つのプロセスに収めるため、アプリはデモのサーバーの中で動いています。
実際にはお客さまのスマホで動き、鍵はスマホから出ません。
